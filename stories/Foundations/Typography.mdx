# Typography

**IBM Plex Sans** for all UI, **IBM Plex Mono** for eyebrow/caption labels, IDs, numeric values, and code. Base 16px. Headings are semibold (600) with tightened tracking for a crisp, technical hierarchy; body copy is Regular (400) with generous line height for dense, data-rich screens.

## Type scale

Type is the workhorse of a data-dense product — every screen is text- and number-heavy. The scale uses 13 MUI variants with weights chosen for legibility at each size. Font families are limited to IBM Plex Sans and IBM Plex Mono — no decorative or branded display faces.

### Font families

| Family | Purpose | Weights |
| --- | --- | --- |
| IBM Plex Sans | All UI text — headings, body copy, buttons, labels | 400 (Regular), 500 (Medium), 600 (Semibold), 700 (Bold) |
| IBM Plex Mono | Eyebrow/caption labels, IDs, numeric values, code | 400, 500, 600 |

**Why IBM Plex Sans?** IBM Plex Sans is a highly legible, screen-optimized sans-serif with a large x-height and a precise, engineered feel that suits a technical product. It reads cleanly from 12px captions up to 48px display headings and gives Vael a modern, purposeful voice that stays out of the content's way. It also pairs with IBM Plex Mono as a single type superfamily, so labels and data read as one system.

**Why IBM Plex Mono for labels and numbers?** Fixed-width alignment makes long identifiers (e.g. `req-20240115-abc123`) scannable — you can compare them character-by-character. Proportional fonts produce ragged columns in tables and obscure character-level differences like O vs 0 or l vs 1. Tabular numerals also keep decimal points aligned in metric columns. The mono face carries the "engineered / blueprint" register the system is built on — it's used for the `overline` and `caption` variants so metadata reads as data, not prose.

| h3 | Semibold (600) | 30px | 1.3 | -0.02em | Page titles |
| h4 | Semibold (600) | 24px | 1.35 | -0.015em | Dialog titles, card group headers |
| h5 | Semibold (600) | 20px | 1.4 | -0.01em | Section headings within a page |
| h6 | Semibold (600) | 18px | 1.45 | -0.01em | Subsection headings, card titles |
| subtitle1 | Medium (500) | 16px | 1.5 | 0 | Lead text, form section labels |
| subtitle2 | Medium (500) | 14px | 1.5 | 0 | Supporting subheadings |

| caption | Regular (400) | 12px | 1.5 | 0 | Helper text, timestamps, field descriptions (IBM Plex Mono) |
| overline | Medium (500) | 11px | 1.5 | +0.14em, UPPERCASE | Eyebrow labels, category tags (IBM Plex Mono) |

**Why headings tighten their tracking?** Optical spacing compensation. At larger sizes (h1: 48px) the visual gap between letters reads wider than intended — a negative track (−0.01em to −0.03em, tighter as the size grows) restores density and keeps display headings feeling deliberate. Body and small text sit at the default (0) tracking, where IBM Plex Sans is already tuned for legibility; the `overline` eyebrow does the opposite — a wide +0.14em track spaces out the uppercase mono label.

### Weight rationale

- **Regular (400)** — The workhorse. Default for body copy, captions, and input text.
- **Medium (500)** — Subtitles, supporting labels, and the `overline` eyebrow.
- **Semibold (600)** — All headings (`h1`–`h6`) and `button`. This is the system's primary emphasis weight and the recognition pattern for headings and interactive labels.
- **Bold (700)** — Available in the family for inline emphasis within body copy; not used by the default variant scale.

Buttons use `textTransform: none` — labels are sentence case, not uppercase. Uppercase is reserved for the `overline` eyebrow.

### Usage guidelines

- **Headings** use `h1`–`h6` semantically — the variant also sets the HTML tag. Override with `component="h1"` when the semantic tag should differ from the visual scale.
- **Body copy** defaults to `body1` for most contexts; use `body2` inside tables, sidebars, dense lists, and metadata blocks.
- **Buttons** always use the `button` variant — do not override weight or case.
- **Captions** are for supplementary metadata (timestamps, helper text). They render in IBM Plex Mono and should never carry primary information a user needs to complete a task.
- **Overlines** are eyebrow labels above a heading — uppercase IBM Plex Mono; use sparingly to categorize a page or section.
- **Monospace** (IBM Plex Mono) is the default for the `overline` and `caption` variants, and can be applied via `fontFamily` on any IDs or numeric fields that benefit from fixed-width alignment.

### Accessibility

- Minimum body size is `body2` (14px) — below that, legibility degrades significantly.
- Line length should target 45–75 characters for body copy. A page-level max-width of ~820px caps `body1` at roughly 72 characters.
- Never use `text.disabled` for content a user must read — it's reserved for inactive controls.
- All headings must follow document hierarchy (h1 → h2 → h3, no skipping) for screen readers. Use `component="hN"` to override the visual variant if needed.

# Typography

**IBM Plex Mono is the system's default** — headings, labels, inputs, table cells, list items, chips, and all UI/data read mono. **IBM Plex Sans** is reserved for long-form prose (body copy, descriptions) and button labels. Base 16px. This **mono-dominant** split matches the Vael case-study page exactly: mono for the interface, sans for reading.

## Type scale

Type is the workhorse of a data-dense product — every screen is text- and number-heavy. The scale uses 13 MUI variants with weights chosen for legibility at each size. Font families are limited to IBM Plex Sans and IBM Plex Mono — no decorative or branded display faces.

### Font families

| Family | Purpose | Weights |
| --- | --- | --- |
| IBM Plex Mono | **The default** — headings, labels, inputs, table cells, list items, chips, IDs, numeric values, code | 400, 500, 600 |
| IBM Plex Sans | Long-form prose (body copy, descriptions) + button labels + subtitles | 400 (Regular), 500 (Medium), 600 (Semibold), 700 (Bold) |

**Why IBM Plex Mono for headings and data?** The mono face carries the "engineered / blueprint" register the system is built on — headings read as precise, technical labels rather than editorial display type, which is the identity Vael and its case-study page share. Fixed-width alignment also makes long identifiers (e.g. `req-20240115-abc123`) scannable character-by-character and keeps numeric columns and decimal points aligned. So the whole "structural" layer — headings, overlines, captions, table headers, tooltips, and data — is Mono.

**Why IBM Plex Sans for body?** Long-form reading wants a proportional face. IBM Plex Sans is a highly legible, screen-optimized sans-serif with a large x-height that reads cleanly in dense, data-rich screens, and it pairs with IBM Plex Mono as a single type superfamily so body and structure read as one system. Button labels stay Sans too, so the primary actions feel approachable next to the mono interface (input *values* are data, so they're mono).

### Full variant scale (13 tokens)

| Variant | Family | Weight | Size | Line height | Letter spacing | Usage |
| --- | --- | --- | --- | --- | --- | --- |
| h1 | **Mono** | Semibold (600) | 48px | 1.15 | -0.04em | Page-level display headlines |
| h2 | **Mono** | Semibold (600) | 36px | 1.2 | -0.03em | Major section headlines |
| h3 | **Mono** | Semibold (600) | 30px | 1.25 | -0.025em | Page titles |
| h4 | **Mono** | Semibold (600) | 24px | 1.3 | -0.02em | Dialog titles, card group headers, stat numbers |
| h5 | **Mono** | Semibold (600) | 20px | 1.35 | -0.015em | Section headings within a page |
| h6 | **Mono** | Semibold (600) | 18px | 1.4 | -0.01em | Subsection headings, card titles |
| subtitle1 | Sans | Medium (500) | 16px | 1.5 | 0 | Lead text, form section labels |
| subtitle2 | Sans | Medium (500) | 14px | 1.5 | 0 | Supporting subheadings |
| body1 | Sans | Regular (400) | 16px | 1.6 | 0 | Primary body copy — the default |
| body2 | Sans | Regular (400) | 14px | 1.55 | 0 | Secondary body — tables, sidebars, dense UI |
| button | Sans | Semibold (600) | 14px | 1.5 | 0, no transform | All button labels |
| caption | **Mono** | Regular (400) | 12px | 1.5 | 0 | Helper text, timestamps, field descriptions |
| overline | **Mono** | Medium (500) | 11px | 1.5 | +0.14em, UPPERCASE | Eyebrow labels, category tags |

**Why headings tighten their tracking?** IBM Plex Mono's glyphs are wide (monospaced), so display sizes need a firm negative track to read as deliberate headings rather than spaced-out code. The track tightens with size (h6 −0.01em → h1 −0.04em) to hold density at the top of the hierarchy. Body and small sans text sit at the default (0) tracking, where IBM Plex Sans is already tuned for legibility; the `overline` eyebrow does the opposite — a wide +0.14em track spaces out the uppercase mono label.

### Weight rationale

- **Regular (400)** — The workhorse. Default for body copy, captions, and input text.
- **Medium (500)** — Subtitles, supporting labels, and the `overline` eyebrow.
- **Semibold (600)** — All headings (`h1`–`h6`) and `button`. This is the system's primary emphasis weight and the recognition pattern for headings and interactive labels.
- **Bold (700)** — Available in the family for inline emphasis within body copy; not used by the default variant scale.

Buttons use `textTransform: none` — labels are sentence case, not uppercase. Uppercase is reserved for the `overline` eyebrow.

### Usage guidelines

- **Headings** use `h1`–`h6` semantically — the variant also sets the HTML tag. Override with `component="h1"` when the semantic tag should differ from the visual scale.
- **Body copy** defaults to `body1` for most contexts; use `body2` inside tables, sidebars, dense lists, and metadata blocks.
- **Buttons** always use the `button` variant — do not override weight or case.
- **Captions** are for supplementary metadata (timestamps, helper text). They render in IBM Plex Mono and should never carry primary information a user needs to complete a task.
- **Overlines** are eyebrow labels above a heading — uppercase IBM Plex Mono; use sparingly to categorize a page or section.
- **Monospace** (IBM Plex Mono) is the default for all **headings** (`h1`–`h6`) and the `overline` / `caption` variants, and can be applied via `fontFamily` on any IDs or numeric fields that benefit from fixed-width alignment. Body, subtitles, and buttons stay IBM Plex Sans.

### Accessibility

- Minimum body size is `body2` (14px) — below that, legibility degrades significantly.
- Line length should target 45–75 characters for body copy. A page-level max-width of ~820px caps `body1` at roughly 72 characters.
- Never use `text.disabled` for content a user must read — it's reserved for inactive controls.
- All headings must follow document hierarchy (h1 → h2 → h3, no skipping) for screen readers. Use `component="hN"` to override the visual variant if needed.

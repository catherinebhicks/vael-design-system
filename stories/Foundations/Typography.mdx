# Typography

**IBM Plex Mono is the whole system** — every variant renders mono. Headings, prose, labels, inputs, table cells, list items, chips, button labels, and all UI/data read in one typeface. Base 16px. This **single-typeface** approach matches the Vael case-study page exactly: one engine-room voice, top to bottom, so nothing reads out of place.

## Type scale

Type is the workhorse of a data-dense product — every screen is text- and number-heavy. The scale uses 13 MUI variants with weights chosen for legibility at each size. There is exactly one family — IBM Plex Mono — no decorative or branded display faces, and no secondary body face.

### Font family

| Family | Purpose | Weights |
| --- | --- | --- |
| IBM Plex Mono | **The entire system** — headings, prose, subtitles, button labels, inputs, table cells, list items, chips, IDs, numeric values, code | 400 (Regular), 500 (Medium), 600 (Semibold), 700 (Bold) |

**Why IBM Plex Mono for everything?** The mono face carries the "engineered / blueprint" register the system is built on — headings read as precise, technical labels rather than editorial display type, which is the identity Vael and its case-study page share. Fixed-width alignment also makes long identifiers (e.g. `req-20240115-abc123`) scannable character-by-character and keeps numeric columns and decimal points aligned. Rather than split the system between a mono "structural" layer and a proportional body face, Vael commits to a single typeface: headings, overlines, captions, table headers, tooltips, prose, buttons, and data all render in Mono, so nothing reads out of place and the whole product speaks one voice.

**What about long-form reading?** A single mono face is an unusual choice for body copy, but it is deliberate — the system is data-dense rather than editorial, and IBM Plex Mono's large x-height and even color hold up well at reading sizes. Prose and button labels keep their own **weights** (body 400, buttons 600) for hierarchy; only the family is shared. Input *values* were always data, so keeping them mono now simply matches the rest of the interface.

| h5 | **Mono** | Semibold (600) | 20px | 1.35 | -0.015em | Section headings within a page |
| h6 | **Mono** | Semibold (600) | 18px | 1.4 | -0.01em | Subsection headings, card titles |
| subtitle1 | **Mono** | Medium (500) | 16px | 1.5 | 0 | Lead text, form section labels |
| subtitle2 | **Mono** | Medium (500) | 14px | 1.5 | 0 | Supporting subheadings |
| body1 | **Mono** | Regular (400) | 16px | 1.6 | 0 | Primary body copy — the default |
| body2 | **Mono** | Regular (400) | 14px | 1.55 | 0 | Secondary body — tables, sidebars, dense UI |
| button | **Mono** | Semibold (600) | 14px | 1.5 | 0, no transform | All button labels |
| caption | **Mono** | Regular (400) | 12px | 1.5 | 0 | Helper text, timestamps, field descriptions |
| overline | **Mono** | Medium (500) | 11px | 1.5 | +0.14em, UPPERCASE | Eyebrow labels, category tags |

**Why headings tighten their tracking?** IBM Plex Mono's glyphs are wide (monospaced), so display sizes need a firm negative track to read as deliberate headings rather than spaced-out code. The track tightens with size (h6 −0.01em → h1 −0.04em) to hold density at the top of the hierarchy. Body and small text sit at the default (0) tracking, where Mono at reading sizes is comfortable; the `overline` eyebrow does the opposite — a wide +0.14em track spaces out the uppercase mono label.

### Weight rationale

- **Regular (400)** — The workhorse. Default for body copy, captions, and input text.
- **Medium (500)** — Subtitles, supporting labels, and the `overline` eyebrow.
- **Semibold (600)** — All headings (`h1`–`h6`) and `button`. This is the system's primary emphasis weight and the recognition pattern for headings and interactive labels.
- **Bold (700)** — Available in the family for inline emphasis within body copy; not used by the default variant scale.

Buttons use `textTransform: none` — labels are sentence case, not uppercase. Uppercase is reserved for the `overline` eyebrow.

### Usage guidelines

- **Headings** use `h1`–`h6` semantically — the variant also sets the HTML tag. Override with `component="h1"` when the semantic tag should differ from the visual scale.
- **Body copy** defaults to `body1` for most contexts; use `body2` inside tables, sidebars, dense lists, and metadata blocks.
- **Buttons** always use the `button` variant — do not override weight or case.
- **Captions** are for supplementary metadata (timestamps, helper text). Like everything else they render in IBM Plex Mono, and should never carry primary information a user needs to complete a task.
- **Overlines** are eyebrow labels above a heading — uppercase IBM Plex Mono; use sparingly to categorize a page or section.
- **Monospace** (IBM Plex Mono) is the single family for the whole scale — headings, prose, subtitles, buttons, and the `overline` / `caption` variants — so IDs and numeric fields already render fixed-width without any per-element `fontFamily` override.

### Accessibility

- Minimum body size is `body2` (14px) — below that, legibility degrades significantly.
- Line length should target 45–75 characters for body copy. A page-level max-width of ~820px caps `body1` at roughly 72 characters.
- Never use `text.disabled` for content a user must read — it's reserved for inactive controls.
- All headings must follow document hierarchy (h1 → h2 → h3, no skipping) for screen readers. Use `component="hN"` to override the visual variant if needed.

### Guidelines

#### Do

- Reference tokens by name (`primary.main`) — never raw hex.
- Use `_states/*` tokens for interactive overlays.
- Follow the chart variable color assignments everywhere.
- Pair `primary.main` with `primary.contrastText` on colored surfaces.

#### Don't

- Hardcode color values in components.
- Use `primary.main` for decorative, non-interactive elements.
- Mix state overlays — only one overlay active at a time.
- Reassign chart variable colors without a formal decision.

## Full token reference

Every color token, in every role. Each token communicates intent rather than a raw value, which keeps application consistent across components and simplifies future theme changes (e.g. dark mode). All colors are defined as semantic variables and must be referenced by token name, never hardcoded as hex values.

### Text — body copy, labels, and supporting content

| Token | Value | Usage |
| --- | --- | --- |
| text/primary | #000000 (87%) | Body text, headings |
| text/secondary | #000000 (60%) | Supporting text, captions |
| text/disabled | #000000 (38%) | Inactive/disabled text |

**Why 87%, 60%, and 38%?** These are Material Design's specified opacity values for text on white. Each was chosen to hit a specific contrast ratio: 87% opacity black on white achieves ~13:1 contrast (well above WCAG AA's 4.5:1 minimum); 60% achieves ~6:1 (AA-compliant for normal text); 38% is intentionally below threshold because disabled elements are exempt from contrast requirements under WCAG 1.4.3.

### Tonal ramps — 6-stop scales for depth, dark mode, and fills

Each semantic color has a full tonal ramp. The 50 and 100 stops are for tinted surface fills (alert backgrounds, tag fills, status row tints) — never use them as text colors. The 300 stop is decorative fill only. The 700 / 800 / 900 stops are high-contrast values for text on white or dark-mode reversed surfaces. The existing `main` and `dark` tokens map to specific stops in each ramp and are still the primary interactive reference.

| Ramp | Stops |
| --- | --- |
| primary | 50, 100, 300, main, dark, 900 |
| secondary | 50, 100, 300, main, dark, 900 |
| error | 50, 100, 300, main, dark, 900 |
| warning | 50, 100, 300, main, dark, 900 |
| info | 50, 100, 300, main, 800, dark |
| success | 50, 100, 300, 700, main, dark |

**Which stop to use?** `50` — alert/chip background, status row tint, tag fill. `100` — hover fill on a tinted surface, icon container bg. `300` — decorative illustration fill, chart area opacity alternative (prefer opacity tokens for charts). `700/800` — text on white when `main` fails AA (rare). `900` — dark mode surface text, maximum contrast variant. In dark mode, the ramp inverts: use `100`–`300` for text on dark surfaces.

### Neutral surfaces — cool-grey ramp for layering without brand color

Use these to create visual depth and hierarchy — panel backgrounds, card resting states, table header fills, inset content areas. These tokens are the answer to "I need a slightly different background but don't want to use a semantic color." All surfaces support `text/primary` at ≥ 7:1 contrast. Use `surface-inverse` for code blocks, dark tooltips, or any inverse-text element.

| Token | Value | Usage |
| --- | --- | --- |
| --ds-surface-1 | #F8FAFC | Sidebar bg, page section bg, very subtle |
| --ds-surface-2 | #F1F5F9 | Card default, panel background |
| --ds-surface-3 | #E2E8F0 | Inset content, secondary panels |
| --ds-surface-4 | #CBD5E1 | Table header, dense background fills |
| --ds-surface-inverse | #1E293B | Dark tooltips, code blocks, 14.6:1 vs white |

#### Use neutral surfaces when

- You need a panel or card to sit behind another panel (depth without color).
- A table header needs weight without using primary blue.
- Alternating row backgrounds for dense data tables.
- Sidebar and navigation backgrounds need separation from content.

#### Don't use neutral surfaces for

- Status or semantic meaning — use tonal ramp 50/100 stops instead.
- Interactive elements — use action overlay tokens (hover, selected).
- Chart fills — use opacity tokens with a specific chart color.
- Mixing with tonal ramp stops in the same component.

### Opacity scale — state layers and chart fills

Opacity tokens define the alpha channel for interactive state layers and chart fills. Apply them as CSS `opacity` or as the alpha in an `rgba()` with a color token — never hardcode an arbitrary opacity value. Each value maps to a specific interaction state in the Material Design state layer model.

| Token | Value | When to use |
| --- | --- | --- |
| --ds-opacity-hover | 0.04 | Mouse hover over a surface or list item. The faintest signal — just enough to acknowledge the cursor. |
| --ds-opacity-selected | 0.08 | A row, chip, or item is actively selected. Use on top of the element's resting background. |
| --ds-opacity-focus | 0.12 | Keyboard focus ring fill (behind the outline). Also used for pressed / active tap state. |
| --ds-opacity-pressed | 0.12 | Active / tap state. Same value as focus — they are mutually exclusive so the equality is intentional. |
| --ds-opacity-dragged | 0.16 | Drag-in-progress state. Highest interactive state signal before an element is "fully active." |
| --ds-opacity-disabled | 0.38 | Opacity of the disabled element's content (text, icon). Applied to the element itself, not a surface layer. |
| --ds-opacity-chart-fill | 0.12 | Area fill under a line series. Matches focus opacity — creates a light halo without obscuring the data. |
| --ds-opacity-chart-tolerance | 0.09 | Tolerance band behind a threshold line. Keep below 0.12 or it overwhelms the line. |
| --ds-opacity-chart-annotation | 0.06 | Debug annotation plot bands. Always the lowest opacity — these are reference overlays, not primary data. |

**Stacking rule.** State layers stack on top of each other: a selected + hovered item is 0.08 + 0.04 = 0.12 total. Do not apply both to the same element simultaneously in a way that adds unexpected visual weight — use a single combined state token when needed. Chart fill opacities should never stack: only one fill band per chart region.

### Brand palette — reference only, not used in product UI

These CSS custom properties document the Vael marketing brand colors as CSS tokens. They are defined in `tokens.css` under the `--ds-brand-*` namespace and are not intended for product UI chrome — semantic tokens (`primary.*`, `success.*`, etc.) govern all interactive product surfaces. Use brand tokens only in explicitly brand-facing contexts (marketing banners, public nav). Two of these colors fail WCAG AA and must never carry text.

| Token | Value | Contrast and usage |
| --- | --- | --- |
| --ds-brand-blue | #3266C0 | 5.5:1 ✓ PASS AA — Any text size, buttons, icons, and borders on white |
| --ds-brand-blue-tint | #EBF0FB | Background/surface only — text placed on top must independently meet 4.5:1 against this surface |

| --ds-brand-green-light | #ABD4A5 | 1.7:1 ✗ FAIL — Background/surface only; text on top must independently meet 4.5:1 (Off-Black #282828 achieves 8.7:1 on this surface) |
| --ds-brand-green-light-tint | #EDF5EB | Background/surface only — text on top must independently meet 4.5:1 (Off-Black #282828 achieves this) |
| --ds-brand-grey | #EDEDED | Background/surface only — text on top must independently meet 4.5:1 (Off-Black #282828 achieves 11.1:1 on this surface) |
| --ds-brand-grey-text | #767676 | 4.5:1 ✓ PASS AA — Minimum-compliant grey for normal text on white; any text size, UI components |
| --ds-brand-off-black | #282828 | 14.8:1 ✓ PASS AAA — Any text size, any use; exceeds all WCAG thresholds on white and light surfaces |
| --ds-brand-white | #FFFFFF | Background/surface — text placed on top must independently meet 4.5:1 |

**WCAG AA quick reference.** Normal text requires 4.5:1 contrast (WCAG 1.4.3). Large text (≥18 px regular or ≥14 px bold) requires 3:1. UI components and graphical objects also require 3:1 (WCAG 1.4.11). Decorative elements have no contrast requirement. For background-only colors, the background itself carries no contrast obligation — the text color placed on top must meet the applicable threshold independently. All contrast ratios listed assume white (#FFFFFF) as the opposing surface unless otherwise noted.

### Chart metric color semantics

Most metric colors map to semantic tokens. The exception is Memory, which uses a dedicated chart-only value (`#00796B`) that does not correspond to any semantic role. This separation exists because `error.main` (red) is reserved exclusively for alert and error states — using it for a routine metric would undermine the alert signal. See the Data Visualization Palette section below for the full chart color reference.

**Why these assignments?** CPU uses blue (primary) as the most central measurement; Throughput uses green (success) because high throughput is a positive outcome indicator; Requests uses purple (secondary) as a secondary parameter; Latency uses orange (warning) because latency issues often precede alerts; Bandwidth uses info blue as an informational metric. Memory was previously mapped to red but was reassigned to teal — red is now reserved solely for alerts and error states. Once assigned, metric color mappings are permanent; changing them breaks visual recognition across all historical charts and reports.

### Accessibility

- `text/primary` on `background/default` achieves WCAG AA contrast (minimum 4.5:1 for normal text).
- `text/secondary` should only be used for supplementary content where reduced contrast is acceptable.
- `text/disabled` intentionally falls below WCAG thresholds — disabled elements are exempt from contrast requirements per WCAG 1.4.3.
- Always pair `primary/main` with `primary/contrastText` when text appears on a colored surface.

### Known accessibility limitations

- **CPU vs Bandwidth** — `#1976D2` and `#0288D1` are both blue and can be difficult to distinguish without labels, especially for users with tritanopia. Legend labels are required whenever both appear in the same chart.
- **Latency orange** — `#EF6C00` is at the 3:1 floor for graphical elements. Do not use it for text labels smaller than 18px; always pair with a legend or axis label.
- **Red/green** — Alert red (`#D32F2F`) and Throughput green (`#2E7D32`) are indistinguishable to deuteranopes (~8% of men). Never rely on these two colors alone to convey different states — use shape, line-style, or position as a second signal.

### Usage rules

#### Do

- Use `--ds-chart-variable-*` tokens in all chart components.
- Always include a legend or axis label — never use color as the only differentiator.
- Use alert red exclusively for alert and error states.
- Treat these assignments as permanent — changing them breaks historical chart recognition.

#### Don't

- Use chart variable colors in UI components (buttons, chips, alerts).
- Use alert red for memory or any routine metric.
- Introduce new chart colors without a formal design decision and ADR.
- Hardcode hex values — always reference the token.

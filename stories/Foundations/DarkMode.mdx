# Dark mode

Dark mode **ships**. Vael exports a full dark palette alongside the light one, and both share the same typography, shape, shadows, and component overrides — only the palette differs. In this Storybook, the sun/moon toggle in the toolbar flips the chrome, components, and docs together.

## How it works

The library exports two ready-made themes from its entry point:

| Export | Description |
| --- | --- |
| `theme` | The default **light** Blueprint theme. |
| `darkTheme` | The **dark** (Engine-Room) counterpart — same typography/shape/overrides, dark palette. |

Wrap your app in whichever the user has selected:

```tsx
import { ThemeProvider, CssBaseline } from '@mui/material';
import { theme, darkTheme } from 'vael-design-system';

<ThemeProvider theme={isDark ? darkTheme : theme}>
  <CssBaseline />
  {/* app */}
</ThemeProvider>
```

Charts follow automatically — `buildVcThemeOptions(theme)` re-derives axis, grid, label, and tooltip colors from the active palette on each render, so no chart-specific dark handling is needed.

## Palette

Both modes draw from the shared Blueprint tokens. The dark mode is a near-black "engine room": a deep background, lighter panels that lift off it, and a brighter blue accent for legibility on dark.

| Token | Light value | Dark value |
| --- | --- | --- |
| background.default | #E9EFF7 | #0A0E14 |
| background.paper | #FFFFFF | #111925 (lifted panel) |
| text.primary | #141C28 | #DCE6F2 |
| text.secondary | #54637A | #8A9BB2 |
| divider | #DBE4F0 | #1E2A3A |
| primary.main | #1976D2 | #42A5F5 (brighter accent on dark) |
| error.main | #D32F2F | #F44336 |

## Design rules for mode-safe UI

- Never hardcode `color: '#fff'`, `background: 'white'`, or `border: '1px solid #e0e0e0'`. Always use semantic tokens (`background.default`, `text.primary`, `divider`, `primary.main`, …) so a component works in both modes automatically.
- Use `background.paper` for any surface that should "lift" off the background — in dark mode it's slightly lighter than `background.default` rather than identical.
- Avoid pure black (`#000000`) as a background — the dark theme uses `#0A0E14`, which is softer and carries the blueprint grid.
- Test color contrast in **both** modes. A primary color that hits AA on light may fail on dark — that's why `primary.main` brightens to `#42A5F5` in dark mode.

## Notes

- **Charts** re-theme per mode via `buildVcThemeOptions` — no per-chart dark work required.
- **System preference** (`prefers-color-scheme`) detection and a persisted toggle are app-level concerns; this Storybook uses `storybook-dark-mode` to drive the toggle, and consuming apps can wire their own.

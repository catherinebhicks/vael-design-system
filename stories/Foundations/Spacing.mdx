# Spacing

An 8px base unit with an 8-step scale. All padding, margin, and gap values are multiples of the 8px base. The scale stops at 8 steps — values beyond 64px are layout-level concerns (percentage widths, Grid columns, viewport units) rather than spacing tokens.

## The 8px grid, explained

All padding, margin, and gap values in the system are derived from a single base unit of 8px. This creates a consistent rhythm across the interface — components and layouts align to an invisible grid regardless of who built them or when. The token scale stops at 8 steps (64px) because values beyond that are layout concerns, not spacing concerns.

### Base unit

The base unit is **8px**. MUI's `theme.spacing(n)` function multiplies a scalar by 8 to produce a pixel value — `theme.spacing(2)` returns `16px`.

**Why 8px?** 8px is the standard base unit in Material Design and most modern design systems. It's divisible by 2 and 4 for half-steps (4px, 2px), aligns naturally with common screen densities, and produces layouts that feel balanced without looking mechanical. Smaller bases (4px) create too many increments and weaken rhythm; larger bases (12px, 16px) are too coarse for dense UI like tables and toolbars.

### Full scale — 8 steps, 8px–64px

| Token | Multiplier | Value | Primary usage |
| --- | --- | --- | --- |
| spacing/1 | 1 | 8px | Icon-to-label gaps, inline spacing between related items, tight chip groups |
| spacing/2 | 2 | 16px | The default. Internal component padding, form field row spacing, button groups, list item gaps |
| spacing/3 | 3 | 24px | Card and panel padding, section internal spacing, dialog padding |
| spacing/4 | 4 | 32px | Gaps between card groups, spacing below section headings, form section breaks |
| spacing/5 | 5 | 40px | Spacing between major page sections |
| spacing/6 | 6 | 48px | Long-form content breaks, gap between primary and supporting content |
| spacing/7 | 7 | 56px | Large layout gaps on desktop, page-level vertical rhythm |
| spacing/8 | 8 | 64px | Max standard spacing — hero sections, marketing layouts |

### Half-step (sub-unit) usage

The system occasionally uses **4px** (`theme.spacing(0.5)`) for fine-grained adjustments — primarily icon alignment within text, chip spacing, and dense table cell padding. Half-steps are allowed but should be rare — if you find yourself reaching for 4px often, reconsider the layout.

- **4px** — Icon micro-adjustment, chip padding (internal), tooltip padding.
- **2px** (`spacing(0.25)`) — Reserved for micro-adjustments. Do not use for component padding.

### Why the scale stops at 64px

Values larger than 64px should be expressed as layout units, not spacing tokens. For full-page layout decisions use:

- **Percentage widths** (`width: 50%`) for responsive column splits.
- **Viewport units** (`100vh`, `80vw`) for full-screen composition.
- **MUI Grid / Container** for structured responsive layouts.
- **Max-width constraints** (`maxWidth: 1280`) for reading zones.

**Why this distinction matters.** Spacing tokens describe _relationships between components_ (this label sits 8px from this input). Layout describes _page-level structure_ (content column is 60% of viewport). Mixing them — e.g. using `padding: spacing(20)` for a hero — tightly couples content to viewport and makes responsive behavior harder to reason about.

### Density guidelines

| Context | Default spacing | Notes |
| --- | --- | --- |
| Marketing / external pages | spacing/3–spacing/8 (24–64px) | Generous — optimize for scanability |
| Dashboard panels | spacing/2–spacing/3 (16–24px) | Standard internal rhythm |
| Forms | spacing/2 (16px) between rows | spacing/1 between label and input |
| Tables | spacing/2 (16px) default, spacing/1 (8px) dense | Configured via MUI size prop |
| Toolbars / headers | spacing/1–spacing/2 (8–16px) | Tight — assume frequent interaction |
| Tooltips | 4px (half-step) | Transient, should feel lightweight |

### Common pitfalls

- **Hardcoded pixel values** — `padding: '17px'` breaks the grid and creates off-rhythm layouts. Always use `theme.spacing(n)` or multiples of 8.
- **Mixing units** — Don't combine `em`, `rem`, and `px` for spacing. Use `px` consistently for spacing; reserve `em`/`rem` for typography.
- **Oversized gaps on mobile** — The 8px scale is desktop-first. On viewports &lt;600px, reduce most spacing tokens by one step (e.g. spacing/3 → spacing/2).

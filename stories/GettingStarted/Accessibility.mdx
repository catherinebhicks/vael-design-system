# Accessibility

The library targets WCAG 2.1 AA. MUI components inherit MUI's built-in accessibility; custom components require an independent audit.

## WCAG 2.1 AA

MUI components inherit MUI's built-in WCAG 2.1 AA accessibility. Custom components outside MUI — SideNav, Highcharts, AG Grid, React Flow, and dnd-kit — require independent audit.

### ADR 011 · WCAG 2.1 Level AA Compliance Target

Why 2.1 AA was chosen over 2.0, 2.2, Level A, and AAA.

2.0 is outdated; 2.2 adds criteria not yet required by most procurement. Level A is insufficient for enterprise; AAA is aspirational and has criteria that conflict with product requirements (e.g. 7:1 contrast breaks our semantic palette). AA is the legal baseline and the achievable target.

### ADR 012 · PDF Export Accessibility

Charts in PDF run reports: PNG image + descriptive alt text + data table.

`@react-pdf/renderer` cannot produce PDF/UA-1 certified output. Until a regulated customer requires it, each chart in a PDF export is paired with a data summary table so screen reader users get the information.

## Audit materials

What "audited" means, what we test against, and how results are tracked.

Accessibility audits combine automated tooling, manual keyboard + screen-reader testing, and color-contrast verification against WCAG 2.1 AA. Each audit produces a component scorecard, a list of filed issues, and a status badge that appears in the component doc header.

### Audit scorecard — per component

Every component moves through a five-part scorecard. A component can only be marked Verified AA once all five pass.

| Check | Tool / method | Pass criteria |
| --- | --- | --- |
| Automated scan | @axe-core/react + jest-axe on all Storybook stories | Zero violations at minor + severity |
| Keyboard nav | Manual — Tab, Shift+Tab, Arrow keys, Enter, Space, Escape | All actions reachable and operable without pointer; focus order logical; no focus traps outside modals |
| Screen reader | Manual — VoiceOver (macOS Safari), NVDA (Win Firefox) | Name, role, state announced correctly on focus and on change |
| Contrast | tokens/contrast-report.json — generated from token pairs | Text ≥ 4.5:1; large text and UI ≥ 3:1; state changes distinguishable |
| Reduced motion | Manual — prefers-reduced-motion: reduce | No parallax, no autoplaying transitions, essential motion reduced to fade/opacity |

### Audit status badges

Appear in the component doc header next to the version tag. Click through to the audit record.

- **Verified AA** — All 5 scorecard checks pass; audit signed within the last 12 months.
- **MUI baseline** — Ships unmodified MUI behavior. Inherits MUI's public a11y record; not independently signed off by the team.
- **Audit scheduled** — Component is queued for audit in a specific quarter; MUI baseline in effect until then.
- **Known gaps** — Audit complete, non-blocking issues filed. Component ships with documented workarounds.
- **Not audited** — Third-party / unwrapped library or experimental component. Not eligible for audit yet.

### Audit schedule

The first pass (Q2 2026 – Q1 2027) covers all base MUI components and custom third-party wrappers. After the first pass completes, all components are re-audited on a rolling annual cadence — any component whose Verified AA sign-off is older than 12 months is queued for the next available quarter. Within each quarter, components are prioritized by codebase usage frequency — most-used first — so regressions in high-traffic surfaces are caught earliest.

### Audit artifacts — where results live

- **Audit record** — `docs/accessibility/audits/[component].md` · scorecard results, filed issues, sign-off date, auditor
- **Contrast report** — `tokens/contrast-report.json` · auto-generated nightly from the token graph
- **Issue tracker** — all findings filed under the `a11y` label with severity (blocker / serious / moderate / minor) matching axe's scale
- **Known-gaps registry** — `docs/accessibility/known-gaps.md` · open issues that ship with documented workarounds

### Environments we test against

| Platform | Browsers / AT | Notes |
| --- | --- | --- |
| macOS | Safari + VoiceOver · Chrome + VoiceOver | Primary target — matches primary user workstations |
| Windows | Firefox + NVDA · Edge + Narrator | Secondary target — primarily QA |
| iOS / Android | Safari + VoiceOver · Chrome + TalkBack | Not a primary target; spot-checked on responsive components |

### When AA can't be reached

Third-party components (AG Grid keyboard gaps, React Flow canvas keyboard model) may not meet AA in their shipped state. In those cases, we document the gap, provide a keyboard-accessible alternate surface where required, and file upstream issues with the vendor. The goal is no AA regressions introduced by our code.

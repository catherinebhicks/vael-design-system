# Hooks

The Vael library is deliberately thin on custom hooks. It ships components, a theme, and tokens — not an application runtime — so most of what a product needs (data fetching, notifications, modals, feature flags) is left to the consuming app.

## What Vael actually exports

| Hook / Provider | Purpose |
| --- | --- |
| `DensityProvider` | Sets the display density (`compact` · `regular` · `comfortable`) for a subtree, exposing the scale as context and optional CSS variables. |
| `useDensity` | Reads the current density (and its token scale) from the nearest `DensityProvider`. Use it when a custom component needs to respond to density. |

That is essentially the whole custom-hook surface. Everything else you build on top of Vael is your app's concern, not the library's.

## A historical note

When these components backed **Fermie** — the data-dense bioprocess product Vael was extracted from, now shelved — the Fermie *application* layered a much larger hook library on top: feedback hooks (`useAlert`, `useSnackbarAlert`, `useBanner`, `useNotifications`), overlay hooks (`useModal`, `useConfirmationDialog`), navigation guards (`useWarnBeforeTransition`), real-time data hooks over socket.io and TanStack Query (`LiveSubscriptionProvider`, `useLiveLatest`, `useLiveChart`), and feature-flag hooks over DevCycle (`useFeatureFlag`).

None of those live in this library. They belonged to the Fermie app and depended on Fermie infrastructure (DevCycle, TimescaleDB, socket.io) that the extracted design system does not carry. They're worth knowing about only as an example of the *kind* of app-level layer a product builds around a design system.

## Consumer patterns

If your app needs imperative feedback, modal management, or live data, that layer lives in your app, not in Vael. A typical shape:

- Wrap Vael's `Snackbar` / `Dialog` / `Alert` components in your own hooks (`useToast`, `useConfirm`) so call sites never manage `open` / `anchorEl` state directly.
- Keep data-fetching and real-time concerns (React Query, sockets, feature flags) in app-side providers; pass the resulting values into Vael components as plain props.
- Read `useDensity` from within those wrappers if your feedback surfaces should track the app's density.

Vael stays presentation-only; your hooks supply the behavior.

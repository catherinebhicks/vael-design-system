# When design and code stopped being two jobs

The oldest tax in this work is the handoff. A designer draws a screen. An engineer rebuilds it in code, translating intent into props and pixels into padding. The moment either side moves — a spacing tweak, a new variant, a "quick fix" in a sprint — the two drift, and nobody notices until QA or a customer does. Most design systems exist specifically to slow that drift down. Very few of them close it.

For a while, mine didn't close it either. I had a Figma file and a codebase, and I was the sync layer between them — the same job every design system maintainer quietly does: eyeball the component, eyeball the code, hope they still agree. That's fine at 27 components. It stops being fine at 103.

**So I brought Vael into Figma properly, and I brought AI with it.** The library isn't a moodboard anymore — it's 105 pages, one per component, each with a doc panel that mirrors its Storybook entry: variants, props, DO/DON'T, the same guidance in both places because it's describing the same thing. Real component instances bound to real Blueprint variables, not rectangles with hex codes typed in by hand. If you open the Figma file and open Storybook side by side, they should tell you the same story, because increasingly they're generated from the same intent.

**The part that actually collapses the handoff is the round-trip.** I connect an agent to the live file over Figma's MCP server, point it at a node — a component, a token, a new variant I've just sketched — and ask it to read the design context and the variables in scope. From there it edits the matching file in `src/components/`, updates the token in `vael/` if the change flows through the token layer, and adjusts the story or MDX to match. I'm not translating anymore. I'm describing intent once, at the node, and the agent carries it into both representations. **Code Connect** is what makes that lookup reliable instead of a guess — it maps each Figma component straight to its file, so "find the right component" stops being a search problem.

None of it lands untested. **Nothing merges until it's verified**: `npm run typecheck` has to pass, Storybook has to render the change correctly, and Chromatic has to come back clean before I'll trust the diff. That's the discipline that makes a tireless collaborator safe to work with — speed without a gate is just a faster way to drift, and the whole point was to stop drifting. Even then, I review the diff myself and commit it by hand. Nothing auto-commits. The agent is the translator between Figma and code, not the one deciding the translation is correct.

The handbook I wrote down for this — `docs/onboarding/designing-with-an-llm.md` — names the three things that connection is actually good for: **ingest** (read the system as context so output matches Vael instead of inventing a new one), **design in it** (generate new screens using the real components and tokens, not fresh boxes), and **round-trip** (the sync loop above). All three run over the same MCP connection; the round-trip is just the one that finally makes the handoff a non-event.

One source of truth, read and written from two directions, checked before either side is allowed to believe it. That's what "design and code stopped being two jobs" actually means in practice — not a metaphor about collaboration, a literal description of where the work happens now. It's one more place the method stopped being a trick for building a design system and started being how I run one.
